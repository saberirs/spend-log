# Spenderrr phone app (offline, no cloud)

The phone app is the same Spenderrr as the website, packaged as a real Android app with
[Capacitor](https://capacitorjs.com). Every file is inside the app, so it opens and works with no
internet, never depends on Netlify, and keeps all data on the phone. There is no server and no login.

> Backup of the code before this work: branches `backup/develop-2026-10-31` and `backup/main-2026-10-31`.

## How it works

| Piece | What it does |
|---|---|
| Website files (`index.html`, `backup.js`, `ledger.js`, `reminders.js`, `whatsapp.js`, …) | Used **unchanged**. The live website is not affected by anything here. |
| `native.js` | Only in the app. Gives the app's web view the phone features the website gets from the browser (table below). On the website it does nothing. |
| `build_app.py` | Makes the app bundle `www/`: a copy of the website files plus `native.js`, without the Google Drive id, service worker or Netlify files. Also sets the Android version from `<meta name="app-version">`. |
| `capacitor.config.json` | App id `com.spenderrr.app`, name, bundle folder, phone settings. |
| `android/` | The Android Studio project (generated by Capacitor, with Spenderrr's icons and splash). |
| `tools/android_assets.py` | Makes the Android icons and splash screens from `icon-512.png` / `icon-maskable-512.png`. |
| `testCase/test_native_app.py` | 18 tests: runs the real app bundle with a simulated phone (files, share sheet, notifications). |
| `.github/workflows/android-app.yml` | On GitHub: runs all tests and builds an installable APK for every push to this branch. |

### Website feature → what the app does instead

| On the website | In the app |
|---|---|
| Backup folder you pick (Chrome) | **Documents › spend-expense-backup › Month_Year** on the phone, same files (`spend-log-backup.json` + `.xlsx`). If Documents can't be written, the app's own storage. |
| Downloads (Excel report, backup file, calendar `.ics`) | Saved to **Documents › Spenderrr** and opened in the **share sheet** (Drive, WhatsApp, Gmail, Calendar…). |
| Browser share menu | Android share sheet, with files. |
| WhatsApp / email / Google Calendar links | Open in those apps. |
| Bill reminders as a card and calendar file | Same card **plus real phone notifications** at 9 AM on the reminder day (or the due day if that has passed). Paying a bill moves its next reminder. |
| Google Drive backup | **Hidden in the app for now** (Google blocks its web sign-in inside apps). Device-folder backup and the share sheet replace it. |
| Offline cache (service worker) | Not needed: every file is in the app. |

## Run it on your phone

### Easiest: download the APK GitHub builds

1. Open the repo on GitHub → **Actions** → **Android app** → the latest green run.
2. Under **Artifacts**, download **spenderrr-debug-apk** (a zip with `app-debug.apk`).
3. Send `app-debug.apk` to your Android phone and open it. Allow "Install unknown apps" for the app you opened it from when asked.

This debug build is for testing only (not for the Play Store).

### On your Mac with Android Studio

One-time setup:

1. Install [Android Studio](https://developer.android.com/studio) (it includes the Android SDK and Java).
2. In the project folder: `npm install`

Each time:

```bash
npm run app:build      # python3 build_app.py && npx cap sync android
npm run app:open       # opens the project in Android Studio
```

In Android Studio pick your phone (USB debugging on) or an emulator and press **Run ▶**.

### Tests

```bash
pip install playwright openpyxl && python -m playwright install chromium   # once
npm run app:test                      # phone app tests (20)
python3 testCase/run_tests.py         # website tests (74) — must stay green
python3 testCase/test_reminders.py    # bill reminder tests (22)
```

## Readable build vs protected build

`build_app.py` has two modes:

- **`npm run app:build`** (readable) — the authored scripts (`native.js`, `backup.js`, `ledger.js`, `reminders.js`, `whatsapp.js`) are copied as-is. Use this for day-to-day development and debugging. The tests run against this.
- **`npm run app:build:protected`** (obfuscated) — those scripts are obfuscated with the same settings as the website build (`build.py`), so the JavaScript inside the APK can't be casually copied. **Use this for the Play Store release.** The app's main script in `index.html` is already obfuscated in the repo; `xlsx.full.min.js` (third-party) and the fonts are copied unchanged either way.

Both modes keep every `window.*` name, so the obfuscated app behaves exactly like the readable one (two tests build the protected bundle and run it end to end to prove this). The obfuscator is the `javascript-obfuscator` dev dependency; `npm install` provides it.

## Updating the app

1. Change the website files as usual and raise the version in `index.html` (`<meta name="app-version">`), `sw.js` etc.
2. `npm run app:build` (readable, for testing) or `npm run app:build:protected` (for a release) — copies the new files into the app and sets the Android version (`2026.10.28` → versionName `2026.10.28`, versionCode `202610028`).
3. Build and test, then upload the new release to Google Play.

The website and the app always run the same code; only `native.js` is app-specific.

## Publishing on Google Play

1. **Decide the app id now.** `com.spenderrr.app` (in `capacitor.config.json` and `android/app/build.gradle`) can't change after the first upload.
2. **Create your upload key** (once, keep it and its passwords safe — losing it means you can't update the app):
   ```bash
   keytool -genkey -v -keystore spenderrr-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias spenderrr
   ```
   Keep the `.jks` file **out of git** (store it like a password, e.g. in your password manager plus a USB drive).
3. **Build the protected bundle first**, so the release has obfuscated code:
   ```bash
   npm run app:build:protected
   ```
   Then in Android Studio: **Build → Generate Signed App Bundle / APK → Android App Bundle**, choose the key, build `release`.
   This gives `android/app/release/app-release.aab`. (`npm run app:apk:release` builds a signed-config release APK from the command line once signing is set up.)
4. In [Google Play Console](https://play.google.com/console) (your personal developer account):
   - Create the app "Spenderrr", free.
   - **Privacy policy**: use the URL of `privacy.html` on your website (update it to mention the app; see below).
   - **Data safety**: Spenderrr collects no data and shares none — everything stays on the device.
   - Content rating questionnaire, target audience, store listing (icon 512×512 = `icon-512.png`, screenshots from your phone).
   - Upload the `.aab` to **Internal testing** first, install it from the Play link on your phone, then promote to Production.
5. New personal developer accounts must run a **closed test with testers for a period before production** (Play Console shows the current requirement). Start that early.

## Known limits and next steps

- **Restore after reinstalling on Android 11+**: Android may not let a reinstalled app read the backup files its earlier install wrote to Documents. If "Backup folder on this device" shows nothing after a reinstall, use **Restore from file** and pick `Documents/spend-expense-backup/<Month_Year>/spend-log-backup.json`.
- **Google Drive backup in the app** needs native Google sign-in (an Android OAuth client in Google Cloud plus a sign-in plugin). Worth adding before launch if you want automatic off-phone backups.
- **Notification icon**: Android shows the app icon in the status bar; a white, single-colour small icon looks better (add `ic_stat_spenderrr` and set it in `capacitor.config.json` → `LocalNotifications.smallIcon`).
- **Privacy page**: add a line that the app keeps everything on the phone and can show bill notifications.
- **iPhone app**: needs a Mac with Xcode and the Apple Developer Program ($99/year). Then `npm install @capacitor/ios && npx cap add ios && npx cap open ios`. `native.js` already supports iOS paths.
- **Netlify**: if Netlify publishes this repository's root folder, the new `android/`, `docs/` and `tools/` folders would be publicly readable there. Consider publishing only the website files (or block those paths) before merging into `develop`.
